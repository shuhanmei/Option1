# 基于封闭图形与 MediaPipe 的电脑虚拟钢琴开发任务书

版本：V1.0  
编制日期：2026年10月20日  
状态：第一版实现完成，待真实设备人工验收

本项目面向普通带摄像头的电脑。摄像头拍摄双手，系统追踪指尖；当指尖在画面中进入虚拟琴键的封闭区域并满足悬停条件时，播放相应音符，支持简单旋律与基础和弦演奏。

用户已确认采用“电脑摄像头追踪手指、指尖进入画面中的琴键区域”的交互方式。用户于2026年10月20日明确要求将任务书迁移至 D:\github_clone\Music- 并按任务书开发，已授权在该工作区实施。以下琴键数量、技术栈和参数为第一版建议基线，实施时以本任务书及后续确认的调整为准。

## 一 项目目标与使用边界

1. 无需触摸屏、实体琴键或额外传感器，通过摄像头完成演奏。
2. 将琴键绘制为独立封闭图形，保证可见区域与交互区域一致。
3. 完成手部追踪、位置映射、音符触发、声音播放和视觉反馈的完整流程。
4. 在约定的电脑和浏览器上稳定演示，并提供完整源码、使用说明和测试记录。

本项目中的“触碰”定义为指尖在二维画面中命中琴键区域，不判断手指是否接触真实屏幕或桌面。第一版采用悬停触发，不包含真实桌面接触检测和下压动作识别。

## 二 第一版范围

| 项目 | 要求 |

## 三 用户操作流程

1. 打开应用，查看摄像头摆放和操作提示。
2. 点击“开始演奏”，授权摄像头并启用声音；等待模型与音频准备完成。
3. 将手放入画面，确认指尖标记与视频中的手指重合。
4. 根据个人坐姿调整琴键位置、大小和悬停时间。
5. 移动指尖进入琴键，短暂停留后发音；移出后释放。
6. 根据需要开启多指模式，演奏简单和弦。
7. 点击暂停时停止触发并释放声音；点击结束时关闭摄像头并清理音频资源。

界面分别显示摄像头、模型和音频的就绪状态，避免只显示一个笼统的加载提示。暂停恢复后重新确认指尖状态，不沿用暂停前的悬停计时。

## 四 技术方案与模块职责

建议采用 TypeScript、Vite、MediaPipe Hand Landmarker、Canvas 2D 和 Web Audio API。手部追踪使用 `@mediapipe/tasks-vision`，模型、WASM 与音频资源随项目托管，锁定依赖版本并记录资源来源及许可。

| 模块 | 职责 | 主要输出 |
| --- | --- | --- |
| 摄像头管理 | 申请权限、获取视频、处理设备错误、释放视频流 | 视频帧与设备状态 |
| 手部追踪 | 初始化模型，按时间戳处理新视频帧，识别最多双手 | 手部关键点与左右手信息 |
| 坐标映射 | 统一镜像、缩放、裁剪、留白及画布尺寸转换 | 画布中的指尖坐标 |
| 琴键模型 | 保存封闭轮廓、音符和显示层级，负责绘制与命中检测 | 当前候选琴键 |
| 交互控制 | 坐标平滑、悬停计时、边界滞回、手部关联和丢失处理 | 音符按下及释放事件 |
| 音频引擎 | 预加载采样、多音播放、音量包络和声音清理 | 钢琴声音与音频状态 |
| 界面设置 | 状态展示、视觉反馈、布局调整和设置保存 | 用户配置与交互反馈 |

处理链路：摄像头新帧 → 手部识别 → 指尖提取 → 坐标映射与平滑 → 琴键命中 → 状态机 → 发音与高亮。

MediaPipe Web 推理为同步调用，应将识别放入 Web Worker，主线程负责界面与音频调度。保持最多一个推理任务在途，繁忙时跳过旧帧，避免队列积压。开发初期需验证目标浏览器上的帧传递方案及实际性能。

## 五 核心交互规则

### 琴键几何与坐标

- 每个琴键保存唯一编号、音名、MIDI 音高、封闭路径、层级和采样映射。
- 绘制与命中检测使用同一份路径数据，黑键重叠区域优先命中黑键。
- 默认采用保持视频比例、完整显示的布局；任何裁剪模式都必须使用相同的显示变换计算指尖位置。
- 镜像只进行一次；视频、关键点和琴键命中必须使用一致的坐标系。
- 窗口缩放、设备像素比变化和琴键布局调整后同步更新变换。调整布局时清理现有触发状态，避免意外发音。

### 悬停与重新触发

每根参与演奏的手指独立维护“区域外、候选悬停、已触发”三个状态。

| 当前情况 | 系统行为 |
| --- | --- |
| 指尖首次进入琴键 | 开始候选悬停计时，显示候选反馈 |
| 连续命中同一琴键达到悬停时间 | 发出一次按下事件，琴键高亮 |
| 指尖持续停留 | 保持占用，不逐帧重新起音；声音可自然衰减 |
| 指尖离开有效释放边界 | 发出释放事件，清除该手指的占用 |
| 指尖切换至其他琴键 | 释放旧琴键，为新琴键重新计时 |
| 指尖离开后再次进入 | 重新满足悬停条件后再次发音 |
| 手部识别丢失 | 取消未完成的悬停；短时保留已触发状态，超时释放 |
| 手部恢复识别 | 重新建立候选状态，不补发丢失期间的音符 |

初始建议值：悬停时间100毫秒，可调范围50至300毫秒；手部丢失释放超时200毫秒。参数均按经过时间计算，不按固定帧数计算，最终默认值根据目标设备实测调整。

使用轻量平滑抑制抖动，进入边界略收缩、释放边界略放宽。边界容差与琴键尺寸关联，不能侵占邻键核心区域；明确命中新琴键时优先执行切键规则。

### 双手与音符占用

- 通过左右手信息、手腕位置和前后帧距离建立短时手部关联，不把结果数组下标作为永久身份。
- 双手交叉或身份无法可靠关联时，清理受影响状态并重新悬停确认。
- 同一琴键由多根手指占用时，仅在首次占用时起音；最后一根手指释放后结束占用。
- 鼠标按下、抬起、移出和窗口失焦均有对应清理逻辑，避免遗留声音。
- 暂停、结束、页面进入后台或推理异常时执行统一的全部音符释放操作。

### 声音规则

- 使用许可允许随项目分发的钢琴采样，记录来源；进入可演奏状态前完成必要音频解码。
- 按下时使用短起音包络，释放时平滑衰减，减少爆音。
- 为每次发音管理独立播放实例，支持多音混合，并预留音量余量避免明显削波。
- 长时间占用不会自动重复播放；钢琴采样自然衰减属于正常行为。
- 用户点击开始按钮时创建或恢复 AudioContext；音频未就绪时明确提示，不显示可演奏状态。

## 七 验收条件与测试用例

验收前记录电脑型号、处理器、摄像头、视频分辨率、浏览器版本、音频输出设备及实际参数。基准环境建议为稳定光照、双手无遮挡、摄像头固定，初始输入分辨率为640×480。

| 验收项 | 测试方法 | 通过条件 |
| --- | --- | --- |
| 画面与映射 | 检查画面中心和边缘，并改变窗口尺寸 | 指尖标记与视频中的指尖对齐，未出现镜像反向或系统性偏移 |
| 琴键命中 | 逐一测试12个琴键及黑白键重叠区 | 音名、声音和高亮一致，重叠区黑键优先 |
| 单次触发 | 指尖在同一琴键停留3秒，重复10次 | 每次仅一次起音事件 |
| 重复弹奏 | 对同一琴键进入、离开20次，每次停留超过阈值 | 每个有效进入均可重新发音，无持续卡音 |
| 多音 | 两指及四指分别命中不同琴键，重复10次 | 各音独立发出，释放关系正确 |
| 同键占用 | 两根手指占用同一琴键，分别移出 | 首次占用起音，最后一个占用者离开才释放 |
| 丢手处理 | 发音后移出摄像头，再重新进入 | 超时释放，恢复后重新确认悬停，无自动补发 |
| 暂停与后台 | 演奏中暂停、切换后台、结束 | 不再产生新音符，活动声音释放；结束后摄像头关闭 |
| 权限与资源异常 | 拒绝摄像头权限、模拟模型或音频加载失败 | 显示具体原因和重试入口，不误显示就绪 |
| 稳定性 | 连续使用15分钟，交替单指和多指 | 无崩溃、无持续卡音，推理队列不增长，无持续资源泄漏迹象 |

性能以目标设备实测为准，建议目标为识别更新率达到24 FPS以上，界面操作无持续卡顿。延迟需分项记录：

- 悬停确认时间：人为设置的交互等待，默认建议100毫秒。
- 系统处理延迟：采集、推理、状态处理及音频调度的耗时。
- 实际动作到出声延迟：包含以上两项及设备输出延迟，不能用代码事件时间差冒充端到端测量。

自动化测试优先覆盖琴键重叠判定、坐标变换、悬停与重新触发、同键多指占用及丢手释放。摄像头跟踪效果和实际声音通过人工验证。弱光、遮挡、快速移动和双手交叉作为边界场景记录结果，不与基准环境混合统计。

## 八 主要风险与处理要求

| 风险 | 处理要求 |
| --- | --- |
| 相邻手指误触 | 默认双食指，提供手指选择，结合悬停确认与边界滞回 |
| 黑键过窄，难以命中 | 提供布局缩放，控制显示密度，先验证一个八度 |
| 摄像头视角造成遮挡 | 提供摆放提示，在M1阶段实际验证单手和双手姿态 |
| 平滑造成延迟 | 将平滑与悬停参数分开调试，记录响应与误触的取舍 |
| 主线程阻塞 | Worker识别、限制在途任务、只处理新帧并释放帧资源 |
| 模型或音频资源无法加载 | 随项目托管资源，显示加载进度、错误和重试入口 |
| 浏览器限制音频或摄像头 | 明确开始按钮，在HTTPS或localhost环境运行 |
| 采样分发许可不明确 | 使用许可明确的素材并附资源清单 |

## 十一 已确认增量：曲库与逐音跟弹（2026年10月21日）

用户已确认本轮范围并授权实施：键盘扩展到C4～C5共13键，内置3～5首单旋律教学曲，提供选曲、试听、当前目标高亮、正确推进、错误提示、暂停/重新开始及完成结果。实际内置4首，曲目来源与改编方式需在界面注明。

练习使用等待模式，不评价节奏和长音；重复音必须释放后重新触发，成功后等待所有已按下琴键释放。试听与练习互斥，自动播放不得推进练习。结果展示首次命中率、错误次数、完成音符数和排除暂停的有效用时。

曲谱为本地结构化数据，超出音域或含无效时值不得启动。切歌、后台、异常与结束需取消旧任务、释放声音并保留或清空对应状态。验收覆盖完整曲目、连续同音、错误停留、同按多键、试听隔离、切歌加载竞态和原有自由演奏回归。节奏评分、和弦教学、用户上传MIDI及账号功能不在本轮范围。

## 十二 已确认增量：交互与教学体验优化（2026年10月21日）

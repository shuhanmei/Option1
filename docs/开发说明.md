# 虚拟钢琴开发说明

## 实现范围

当前版本实现C4～C5共13个封闭琴键、最多双手追踪、双食指与全部手指两种模式、悬停确认、多音占用、采样钢琴、鼠标与键盘辅助演奏、状态反馈、布局调节、本地设置、暂停结束及错误恢复。2026年10月21日新增4首内置教学曲、逐音指引、试听和练习结果。

全部视频帧仅在本机浏览器中处理。应用没有上传接口、录像、账号或数据库。模型与音频从站点自身加载。

## 坐标与封闭图形

摄像头元素使用 `object-fit: contain` 和水平镜像。`mapPoint` 应用相同的比例和留白，并仅镜像一次。Canvas使用CSS像素作为逻辑单位，设备像素比仅影响背板分辨率。

琴键布局以实际视频内容矩形为基准，避免宽屏留白中的琴键无法被指尖命中。窗口缩放、DPR变化、摄像头就绪或布局调整时重新生成几何并释放现有交互。

白键与黑键均使用矩形闭合路径；绘制与命中共用同一几何数据。黑键后绘制、优先命中。图形模型可扩展为多边形，但需同时替换绘制与命中方法。

## 手部关联与悬停

Worker输出手部关键点与左右手标签。主线程使用手腕距离和标签建立短时身份关联，不依赖识别数组顺序；关联不明确时创建新身份，旧状态超时释放。平滑时间常数为35毫秒，仅用于减小抖动，不预测遮挡期间的位置。

每根手指有独立身份 `hand:手部编号:关键点编号`。默认仅选关键点8；全部手指模式使用4、8、12、16、20。

交互流程为区域外、候选悬停、已触发。进入新键会重新计时，持续停留不重复起音。进入区域略收缩、保持区域略放宽；黑键边缘未达到收缩条件时不回落命中底下白键。默认悬停100毫秒，可调50至300毫秒。

`confirmedMs`只在同一指尖连续有效观察时增加，每次最多增加120毫秒。已知漏检设置`interrupted`：短暂保留原进度，返回第一帧不计入漏检期间的时间。使用最近更新间隔的指数均值计算`graceMs = clamp(cadence × 2.5, 160, 320)`。候选超时清空，已触发的释放等待为`max(200, graceMs)`；过期后重新确认。起音只发生在新识别结果中，绘画循环中的`expire`只能释放，不能发声。圆环读取已确认进度，不能随墙钟自行填满。手部身份允许最多350毫秒的短时关联，实际音符仍由悬停超时独立释放。

`NoteOwners` 统一管理手指、鼠标和键盘。同音第一次占用时起音，最后一个占用者离开后释放。暂停、失焦、结束、布局或交互配置变化时清理全部状态。

## 推理与生命周期

主线程同一时间最多提交一个推理任务，通过可转移的ImageBitmap传入经典Worker。经典Worker支持WASM加载器使用的 `importScripts`；在导入CommonJS包之前创建 `self.exports`。帧处理完成后在 `finally` 中关闭ImageBitmap。

仅处理新的视频时间，采集上限约30 FPS；模型初始化超时45秒、在途推理超时5秒后显示错误并清理会话。超过200毫秒的旧结果不参与交互，避免迟到画面触发声音；冷启动首帧较慢时需等后续结果。

会话具有停止、启动中、运行、暂停、结束中状态。使用代次编号隔离迟到的摄像头权限、模型与音频任务。启动期间结束后，迟到的视频流会立即停止。暂停保留视频流，结束则终止Worker、停止所有摄像头轨道、断开视频并关闭音频。

## 音频

5个预加载采样覆盖C4、D♯4、F♯4、A4、C5，其余音符按最近采样的半音距离调整播放速率。采样自然衰减，停留不会循环播放，也不模拟真实力度。

每次起音创建独立BufferSource，8毫秒渐入；释放时120毫秒渐出。输出经过主音量和动态压缩器，减小多音混合的峰值。结束时停止释放尾音并关闭AudioContext。资源需完整解码后才显示音频就绪；加载失败可重试。

## 曲库、逐音指引与试听

`songs.ts` 使用 `Song` 与 `SongStep` 表示歌曲：每步含MIDI音高和以四分音符为单位的拍数，`null`表示休止。启动前检查速度、时值、音符数与60～72音域。练习提取非休止音符，试听保留全部时值。内置曲目为人工录入的教学版本，来源与修改方式在数据和界面中注明。

`Lesson` 是不依赖DOM的状态机：`idle`（未开始）、`playing`（等待输入）、`release`（成功后等待全部释放）、`paused`（暂停）、`completed`（完成）。`index`既是已完成音符数，也是当前目标下标。主线程将 `NoteOwners` 的有效用户on/off事件同时交给声音模块与练习控制器，避免每个摄像头帧重复计次。

正确on事件只消费一次：记录本步骤是否首次命中，推进下标，再等待内部 `held` 集合清空后接收下一步。错误on事件保留进度、增加错误计数，并显示500毫秒提示；重复on与释放等待期间的起音不重复判定。相同音符由同音占用合并与释放门槛共同防止自动连过。计时使用 `performance.now()`，暂停累积已用时间，继续时重新开始计时，完成后冻结结果。

试听的 `SongPlayer` 将拍数换成秒：每步时长为 `beats × 60 / BPM`。以 `AudioContext.currentTime` 为基准提前80毫秒安排起音、释放与间隔。25毫秒定时器只读取音频时钟并更新提示，不直接控制发声时间。`PianoAudio.schedule` 使用独立播放源集合，不经过 `NoteOwners` 或 `Lesson.input`，因此试听不会自动完成课程。

切歌、返回曲库、重新开始、暂停、失焦与页面隐藏时，先让练习进入暂停状态，再释放用户音符、取消试听源与定时器。`lessonGeneration`隔离旧音色加载完成回调，避免切歌后自动启动旧曲目。两个暂停入口使用同一个`togglePause`，同时暂停摄像头推理和课程，继续时复用已有MediaStream和Worker，不调用`openCamera`。视频连接仍占用摄像头，只有`end`会调用`tracker.stop`释放轨道。可达性检查是显式例外：保留课程暂停，只接收手势检查布局，鼠标不能代替通过。

Canvas将目标边框叠加到现有琴键填充上，蓝框与▼箭头表示目标，绿色表示实际按下，橙色表示错误。白键边框位于下半部，避免被后绘制的黑键遮挡。界面只展示当前目标，后续五个音符显示在独立提示条。

练习不评价节奏、休止或长音。结果中的首次命中率为`firstTry / notes.length`，不会因为等待用户最终弹对而恒为100%。`mistakeSteps`记录错误步骤，用于截取包含上下文的易错片段。`songSection`按非休止音符序号截取，保留段内休止与时值；练习和试听使用相同范围。试听速度仅缩放起止时间，不改变音高。

完成后写入本地键`air-piano:history:v1`，保留最近50轮，显示最近10轮；读回时校验曲目、范围、时间及计数，展示使用`textContent`。统计只比较相同曲目和范围，避免整曲与短片段混比。`recorded`防止绘制或off事件重复保存。循环练习只有完成且所有音符释放后重开；`allowLoop`与`clearingNotes`防止暂停/切歌中的程序清理off意外启动下一轮。

界面每150毫秒刷新简明输入状态；展开诊断时显示识别间隔、旧帧丢弃和触发原因计数。诊断不保存图像与历史，不上传。开始练习/试听时收起曲库与介绍，可通过返回曲库重新选曲。

## 设置与扩展

浏览器存储键为 `air-piano:v1`，读取时校验类型与范围。无效JSON回退默认值，无法持久化时仍允许本次使用。

扩展更多八度时需同时调整琴键、采样映射、布局可用宽度和测试。若加入下压模式，应建立独立触发策略并验证姿态校准；不能将MediaPipe相对深度直接当作真实桌面或屏幕接触距离。

## 开发约束

生产静态部署按域名根路径设计。子路径部署需调整Worker的本地资源路径。素材更新后重新生成资源清单并核对许可。不要提交 `node_modules`、`work`、测试临时目录或凭据。
